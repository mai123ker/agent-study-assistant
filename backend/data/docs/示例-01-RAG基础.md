# RAG 检索增强生成基础

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是把「外部知识检索」和「大模型生成」拼在一起的方案。
它解决的核心问题是：大模型的参数里没有你的私有资料，而且它的知识有截止日期。

RAG 的做法是：用户提问时，先去资料库里检索出最相关的若干片段，
把这些片段拼进提示词，再让模型基于这些片段回答。

## RAG 的四个阶段

1. 索引阶段：文档解析 → 切块 → 向量化 → 入库
2. 检索阶段：查询向量化 → 相似度召回 → 粗排 → 精排
3. 生成阶段：拼接上下文 → 提示词约束 → 模型生成
4. 评测阶段：召回率、答案正确率、延迟、成本

## 切块策略

切块是 RAG 里影响最大的环节之一，却最容易被忽略。

固定长度切块实现最简单，但会把句子从中间切断。
递归字符切块按「段落 → 句子 → 字符」的优先级逐级降级，尽量保住语义边界。
语义切块按句子间相似度切分，效果最好但最慢。

块大小（chunk_size）太小会导致语义不完整，太大则检索精度下降、浪费 token。
块之间保留重叠（overlap）是为了防止一句话正好落在切点上，导致两边都检索不到。

## 混合检索

纯向量检索的弱点是对专有名词不敏感。例如查询「MCP 协议」，向量检索可能返回一堆泛泛讨论「协议」的段落，却漏掉真正写着 MCP 的那一段。

BM25 是经典的关键词检索算法，靠字面匹配，正好补上这个短板。但 BM25 对「换个说法问」无能为力。

所以生产环境通常使用混合检索：向量检索和 BM25 各召回一批，再融合排序。

融合算法常用 RRF（Reciprocal Rank Fusion）。它只看排名不看分数，
因此天然免疫两路分数量纲不同的问题，公式是每个文档累加 1/(k + rank)，k 通常取 60。

## 抑制幻觉

RAG 并不能自动消除幻觉。必须靠提示词约束：

第一，限定回答范围，明确告诉模型只能依据提供的资料回答。
第二，允许模型承认不知道，资料里没有的内容要直接说没有，不要编造。
第三，要求标注引用编号，让答案可核查。

光靠提示词不够，还需要建立包含「拒答类」问题的评测集来量化约束是否生效。
