## 第 1 周 · LLM 调用 + 最小 Agent（Day 1–7）

### Python 后端工程（Day 2 主线）
- [ ] 🔴 async/await：为什么 LLM 调用要异步；并发 vs 并行
- [ ] 🔴 Pydantic：请求/响应模型、自动校验（422 的由来）
- [ ] 🔴 FastAPI 依赖注入 `Depends`：你项目里 `llm_client` 就是这么注入的
- [ ] 🟡 pydantic-settings + `.env`：配置集中管理、改配置必须重启
- [ ] 🟡 pytest：给 `/api/chat` 写接口测试
- [ ] 🟡 统一异常处理：`HTTPException`、自定义错误响应

### LLM API 层（Day 3）
- [ ] 🔴 messages 结构：system / user / assistant 角色与拼接
- [ ] 🔴 多轮对话本质 = 把历史塞回 messages；上下文窗口与 token 成本意识
- [ ] 🔴 temperature / top_p / max_tokens 各自控制什么
- [ ] 🔴 结构化输出：JSON mode + 解析失败的兜底（重试 / 降级）
- [ ] 🟡 OpenAI 兼容接口：DeepSeek / 通义 / Ollama 只换 base_url 和 model
- [ ] 🟢 流式输出的概念（第 3 周动手实现）

### Function Calling（Day 4）
- [ ] 🔴 tools schema：用 JSON Schema 描述函数（name / description / parameters）
- [ ] 🔴 tool_calls 响应结构：一定要打印原始 JSON 看一遍
- [ ] 🔴 完整闭环：发请求 → 解析 tool_calls → 执行 → 结果以 role=tool 回填 → 再生成
- [ ] 🟡 多工具场景：模型怎么选工具、工具的 description 怎么写才准

### Agent 核心模式（Day 5–6）
- [ ] 🔴 手写 ReAct 循环：Thought → Action → Observation（不用任何框架）
- [ ] 🔴 终止条件：最大轮数、拿到最终答案、工具报错
- [ ] 🔴 Plan-and-Solve vs ReAct vs Reflection 的区别与适用场景（高频面试题）
- [ ] 🟡 Agent 的本质：LLM + 工具 + 循环 + 状态管理

### Transformer 最小必备（Day 7）
- [ ] 🟡 Attention 直觉：Q/K/V 各是什么、为什么要除以 √d
- [ ] 🟡 位置编码为什么需要；主流大模型为什么是 Decoder-only
- [ ] 🟡 KV Cache：是什么、为什么省算力、代价是什么
- [ ] 🟢 Encoder-only / Decoder-only / Seq2Seq 的代表模型

## 第 2 周 · RAG + LangGraph（Day 8–14）

### 文档处理与切块（Day 8–9）
- [ ] 🔴 PDF / Markdown 解析：版面、表格、页眉页脚的坑
- [ ] 🔴 切块策略：固定长度 / 递归字符 / 语义切块
- [ ] 🔴 chunk_size 与 overlap 怎么选：太大 / 太小分别出什么问题
- [ ] 🟡 清洗与去重对检索的影响（资料包里的 PDF 就是现成测试数据）

### Embedding 与向量库（Day 10）
- [ ] 🔴 Embedding 本质：文本 → 高维向量，语义相近 → 距离相近
- [ ] 🔴 余弦 / 内积 / L2 三种相似度的区别
- [ ] 🟡 Chroma：建 collection、插入、相似度查询
- [ ] 🟡 Embedding 模型选型：维度、中文能力、怎么验证好坏

### 检索（Day 11–12）
- [ ] 🔴 top_k 与相似度阈值：改参数观察召回变化（四步法第 3 步）
- [ ] 🔴 混合检索：BM25 + 向量为什么要结合、分数怎么融合
- [ ] 🔴 Rerank：Cross-Encoder vs Bi-Encoder，为什么先粗排后精排

### Memory 与上下文工程（Day 13）
- [ ] 🔴 上下文膨胀问题：长对话为什么变慢、变贵、变傻
- [ ] 🔴 控制手段：滑动窗口、历史摘要、裁剪策略
- [ ] 🟢 长期记忆思路：向量库存历史、用户画像（对应面试题库第 12 篇）

### RAG 失败处理（穿插学，面试高频追问）
- [ ] 🔴 检索失败怎么办：query 改写、多路召回、HyDE、诚实拒答
- [ ] 🔴 幻觉缓解：引用来源、限定只根据上下文回答（题库第 71 篇）
- [ ] 🔴 RAG 全链路 + 每个环节的优化点，要能一口气讲完

### LangGraph（Day 14）
- [ ] 🔴 StateGraph 三要素：State、Node、Edge（条件边）
- [ ] 🟡 为什么用图编排：和 if-else 串逻辑的区别
- [ ] 🟢 检查点与状态持久化（概念）

## 第 3 周 · MCP + 工程化（Day 15–21）

### MCP（Day 15–17）
- [ ] 🔴 MCP 是什么、解决什么问题（M×N 集成变成 M+N）
- [ ] 🔴 架构：Host / Client / Server；三类能力 tools / resources / prompts
- [ ] 🔴 自己写一个 MCP Server：暴露 2–3 个工具（读本地资料等）
- [ ] 🔴 MCP 与 Function Calling 的关系与区别（高频面试题）
- [ ] 🟡 传输方式：stdio vs HTTP/SSE

### 工程健壮性（Day 18–20）
- [ ] 🔴 SSE 流式响应：FastAPI `StreamingResponse`，前端逐字渲染
- [ ] 🔴 超时与重试：指数退避；哪些错误该重试、哪些不该
- [ ] 🔴 死循环检测与终止：轮数上限 + 重复动作检测
- [ ] 🔴 工具失败兜底：异常结果格式化后回填给模型，而不是直接崩
- [ ] 🟡 工具权限：白名单、参数校验、危险操作拦截
- [ ] 🟡 结构化日志 + trace id：一次请求全链路可追踪
