## 1. 背景与问题

**用户现状**：学习资料（课件 PDF、笔记）分散存储，查一个知识点要在多个文件里反复翻找；直接问通用大模型，它会"一本正经地胡说"——答案流畅但没有依据，无法用于学习场景。

**核心矛盾**：通用大模型是"记忆题"（凭参数记忆作答），学习场景需要"阅读理解题"（依据给定资料作答并标注出处）。

**产品定位**：一个「上传资料就能问、答案有出处、查不到就明说」的本地学习问答工具，提供 Chat / RAG / Agent 三种对话模式。

## 2. 目标与非目标

**目标（v1.0）**
1. 用户上传 PDF/TXT 资料后，可针对资料内容提问，答案附带来源引用（文件名 + 页码）
2. 资料中没有依据的问题，系统明确回退提示，而非编造答案
3. 涉及计算、时间、文件读取等操作时，Agent 模式可自主选择工具完成并展示执行轨迹
4. 全链路可在本地离线验收（mock 模型 + 确定性向量），不依赖外部 API 即可回归

**非目标（v1.0 明确不做）**
- 多用户/权限体系（定位个人工具）
- 图片/表格 OCR 解析（仅文本层提取）
- 多轮 Agent 规划（单任务循环内完成）

## 3. 目标用户与核心场景

| 用户 | 场景 | 期望 |
|---|---|---|
| 自学者/学生 | 资料多、找不到知识点 | 一次提问直达出处 |
| 学习者 | 对大模型答案不信任 | 每句结论可核对来源页码 |
| 开发学习者 | 想理解 RAG/Agent 原理 | 代码结构清晰、测试可跑、文档可复现 |

**典型用户流程**：
```
上传资料 → 建立索引（解析→切分→向量化）→ 选择模式提问
  ├─ Chat：通用对话
  ├─ RAG：检索资料 → 带引用回答 → 无结果则回退提示
  └─ Agent：模型自主选择工具（检索/计算/时间/读文件）→ 展示每步轨迹 → 给出答案
```

## 4. 功能需求

### P0（核心链路，v1.0 已交付）

| # | 功能 | 需求描述 | 验收标准 |
|---|---|---|---|
| F1 | 文档解析与切分 | PDF/TXT 导入，按标题层级切分、相邻块重叠、页眉页脚清洗 | 切分结果在混合排版课件上不串段（test_splitter） |
| F2 | 混合检索 | BM25（精确词）+ 向量（语义改述）双路召回，RRF 融合排序 | 两种提问风格均能召回正确片段；融合分对分值刻度不敏感（test_retrieval） |
| F3 | 带引用回答 | 答案标注 [编号]，编号对应来源文件+页码；流式输出先给来源再给正文 | 每条结论可反查出处；低温(0.1)保证事实问答稳定 |
| F4 | 无依据回退 | 检索为空时返回固定回退话术（"未检索到相关片段"），并携带 used_context=False 标志 | 空结果不进模型，杜绝无依据生成 |
| F5 | Agent 工具调用 | 模型按 JSON Schema 自主选择工具（get_current_time / calculator / search_docs / read_file），执行结果回填对话 | 工具选择正确率可验收；轨迹记录每步耗时（test_trace_records_duration） |
| F6 | 循环安全终止 | max_steps 上限、重复动作检测（忽略参数键序）、模型失败降级，终止原因落 trace.stopped_by | 四种终止（answer/max_steps/repeat/error）均有测试覆盖 |
| F7 | 工具执行安全 | AST 白名单校验计算表达式、参数 JSON Schema 校验、路径穿越拦截；工具报错格式化回填而非抛异常 | 恶意参数/未知工具/坏 JSON 均不炸服务（test_tools、test_agent） |

## 5. 异常与边界场景（防 Bad Case 设计）

| 场景 | 处理策略 |
|---|---|
| 索引为空 / 检索无结果 | 固定回退话术，不调用模型 |
| 工具执行失败 | 错误文本回填模型（"[工具执行失败] …"），由模型决定换工具或告知用户 |
| 未知工具 / 坏 JSON / 缺参数 | 注册层直接拒绝，返回结构化错误 |
| 模型重复调用同一工具 | repeat 检测终止，trace 标注 stopped_by=repeat |
| 模型服务不可用 | 降级返回错误提示（stopped_by=error），不无限重试烧钱 |
| 文档内容含指令（提示注入） | 不依赖 prompt 约束，代码层白名单 + 参数校验兜底 |

## 6. 数据指标（定义）

| 指标 | 定义 | 用途 |
|---|---|---|
| 检索命中率 | top-k 结果含正确片段的比例 | 评估切分/检索参数调优效果 |
| 回退率 | used_context=False 占比 | 过高说明索引质量差，过低说明回退闸失效 |
| Agent 终止分布 | stopped_by 四类占比 | repeat/max_steps 占比高 → 工具描述或参数 schema 有问题 |
| 工具成功率 | ok=True 占比 | 定位工具实现缺陷 |

## 7. 验收方式

- 全量回归测试套件（116 个测试函数，覆盖切分/检索/Agent/工具/API/记忆），mock 模型 + 确定性哈希向量，**离线可跑、可复现**
- 每个验收标准对应具名测试，Bad Case 修复必须先补回归用例再改代码
- 详见《Bad Case 分析报告》（docs/BadCase-分析报告.md）
